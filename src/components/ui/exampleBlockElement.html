我实际比较关注几个点 {{renderer :blockview, list}
1. work stealing
高并发下能提高 CPU 利用率。
2. syscall 阻塞
如果 goroutine 进入 syscall：
runtime 会解绑 P。
避免整个调度停滞。
这个机制对 IO 密集服务非常关键。
3. goroutine 泄漏
这个是线上高频问题。
比如：
channel 阻塞
ctx 未关闭
retry 风暴
最终会：
内存上涨
调度压力增加
GC 变差
4. GC 与调度耦合
很多人误区 --> GC 只看堆内存对象，跟协程没关系。
但实际上 --> 高 goroutine 数量会影响：
Go 的每个 Goroutine 都有自己独立栈
GC 做标记的时候，必须遍历所有存活 G 的栈

从栈里找指针、找存活对象，防止误回收
不管这个 G 是在干活、还是在睡觉阻塞，只要还活着，栈就得扫
G 越多 → 栈数量越多 → 扫描工作量成倍涨
扫描慢 → 标记阶段拉长、STW 变长
直接后果：
GC CPU 占用飙升
服务定时抖动、接口延迟毛刺
高并发下容易雪崩
我线上一般怎么排查 --> 通常会结合：pprof/trace/runtime metrics/goroutine dump一起分析。
