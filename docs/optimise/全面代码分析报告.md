### 1.2 具体性能问题分析

#### 问题 1：Heatmap 组件 - Resize 事件监听器清理不完整

**影响范围**：`/workspace/src/components/Heatmap/Heatmap.tsx` 182-225 行

**问题描述**：
- 当用户拖动调整大小时，添加的 `mousemove` 和 `mouseup` 监听器没有完整的清理机制
- 如果组件在调整过程中被卸载，会导致内存泄漏

**风险等级**：🟡 中等

**修复建议**：
```typescript
// 添加 ref 存储监听器
const resizeMoveListenerRef = useRef<{ 
  move: (e: MouseEvent) => void, 
  end: () => void 
} | null>(null);

const handleResizeStart = useCallback((e: React.MouseEvent) => {
  // ... 原有代码
  
  const handleResizeMove = (moveEvent: MouseEvent) => { /* ... */ };
  const handleResizeEnd = async () => { /* ... */ };
  
  // 存储到 ref
  resizeMoveListenerRef.current = { move: handleResizeMove, end: handleResizeEnd };
  
  // ... 其余代码
}, [onBlockId]);

// 添加清理 useEffect
useEffect(() => {
  return () => {
    if (resizeMoveListenerRef.current) {
      const doc = getDocument();
      if (doc) {
        doc.removeEventListener('mousemove', resizeMoveListenerRef.current.move);
        doc.removeEventListener('mouseup', resizeMoveListenerRef.current.end);
      }
      resizeMoveListenerRef.current = null;
    }
  };
}, []);
```

#### 问题 2：Toast 组件 - setTimeout 清理和全局挂载

**影响范围**：`/workspace/src/components/Toast/Toast.tsx`

**问题描述**：
1. 快速添加多个 toast 时，timeout 没有完全清理
2. 将 `addToast` 直接挂载到 `window` 对象，类型不安全且可能与其他插件冲突

**风险等级**：🟡 中等

**修复建议**：
```typescript
// 建议 1: 使用 ref 存储所有 timeout
const timeoutRefs = useRef<number[]>([]);

// 添加时存储 id
const id = setTimeout(() => { /* ... */ }, 3000);
timeoutRefs.current.push(id);

// 清理时全部清理
useEffect(() => {
  return () => {
    timeoutRefs.current.forEach(id => clearTimeout(id));
  };
}, []);

// 建议 2: 使用事件总线替代全局挂载
```

#### 问题 3：缺少设置和 DOM 查询缓存

**影响范围**：多个模块，尤其是 BlockView 和设置访问

**问题描述**：
1. `getSettingsWithSystem()` 在多个组件中频繁调用，没有缓存
2. DOM 元素查询没有缓存，可能在频繁更新场景中影响性能

**风险等级**：🟢 低

**修复建议**：
```typescript
// 添加设置缓存
let settingsCache: any = null;
let lastSettingsFetchTime = 0;
const SETTINGS_CACHE_TTL = 1000; // 1秒

async function getCachedSettings(): Promise<any> {
  const now = Date.now();
  if (settingsCache && now - lastSettingsFetchTime < SETTINGS_CACHE_TTL) {
    return settingsCache;
  }
  settingsCache = await getSettingsWithSystem();
  lastSettingsFetchTime = now;
  return settingsCache;
}
```

#### 问题 4：Heatmap 组件的重复计算

**影响范围**：`/workspace/src/components/Heatmap/Heatmap.tsx` 278-349 行

**问题描述**：
- `dynamicStyle` 计算虽然使用了 `useMemo`，但其中的计算函数（如 `getYearWeeksCount`、`calcCell`）每次渲染都重新创建
- 一些纯计算逻辑可以提取到组件外部

**风险等级**：🟢 低

**修复建议**：
```typescript
// 提取到组件外部的纯函数
function getYearWeeksCount(year: number): number {
  const first = new Date(Date.UTC(year, 0, 1));
  const startDayOfWeek = first.getDay();
  const startPadding = startDayOfWeek === 0 ? 6 : startDayOfWeek - 1;
  const days = ((Date.UTC(year + 1, 0, 1) - Date.UTC(year, 0, 1)) / 86400000) | 0;
  return Math.ceil((startPadding + days) / 7);
}
```

#### 问题 5：渲染器参数模块的正则表达式重复创建

**影响范围**：`/workspace/src/lib/render/rendererArgs.ts`

**问题描述**：
- `createRendererArgUpdater` 函数中每次调用都重新创建正则表达式
- `findModel` 函数每次都遍历所有模型

**风险等级**：🟢 低

**修复建议**：
```typescript
// 添加正则表达式缓存
const regexCache = new Map<string, RegExp>();

export function createRendererArgUpdater(prefixes: string | string[]): { /* ... */ } {
  const prefixList = Array.isArray(prefixes) ? prefixes : [prefixes];
  const cacheKey = prefixList.join('|');
  
  let rendererRegex = regexCache.get(cacheKey);
  if (!rendererRegex) {
    // 创建并缓存
    const prefixPattern = prefixList.map(p => 
      p.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')
    ).join('|');
    rendererRegex = new RegExp(`({{renderer\\s+(?:${prefixPattern})[^}]*?}})`, 'gi');
    regexCache.set(cacheKey, rendererRegex);
  }
  
  // ... 其余代码
}
```

#### 建议 2：抽象更多自定义 Hooks
**优先级**：🟡 中

**可抽象的 Hooks**：
1. **useResizeObserver** - 观察元素大小变化
2. **useEventListener** - 统一的事件监听管理

5. **useEventBus** - 事件总线监听

**示例**：
```typescript
// useResizeObserver hook
function useResizeObserver(
  ref: React.RefObject<Element>,
  callback: (entry: ResizeObserverEntry) => void
) {
  useEffect(() => {
    const observer = new ResizeObserver((entries) => {
      entries.forEach(entry => callback(entry));
    });
    
    const element = ref.current;
    if (element) {
      observer.observe(element);
    }
    
    return () => observer.disconnect();
  }, [ref, callback]);
}

// useEventListener hook
function useEventListener<K extends keyof HTMLElementEventMap>(
  element: HTMLElement | null,
  eventName: K,
  handler: (event: HTMLElementEventMap[K]) => void,
  options?: boolean | AddEventListenerOptions
) {
  const savedHandler = useRef(handler);
  
  useEffect(() => {
    savedHandler.current = handler;
  }, [handler]);
  
  useEffect(() => {
    if (!element) return;
    
    const eventListener = (event: HTMLElementEventMap[K]) => {
      savedHandler.current(event);
    };
    
    element.addEventListener(eventName, eventListener, options);
    
    return () => {
      element.removeEventListener(eventName, eventListener, options);
    };
  }, [element, eventName, options]);
}
```

**优先级**：🟡 中

```typescript
class ErrorBoundary extends React.Component<
  { children: React.ReactNode; fallback?: React.ReactNode },
  { hasError: boolean }
> {
  constructor(props: { children: React.ReactNode; fallback?: React.ReactNode }) {
    super(props);
    this.state = { hasError: false };
  }
  
  static getDerivedStateFromError() {
    return { hasError: true };
  }
  
  componentDidCatch(error: Error, errorInfo: React.ErrorInfo) {
    logger.error('组件渲染错误', error, errorInfo);
  }
  
  render() {
    if (this.state.hasError) {
      return this.props.fallback || (
        <div className="ltt-error-fallback">
          <span>出现问题，请刷新页面重试</span>
        </div>
      );
    }
    return this.props.children;
  }
}
```
