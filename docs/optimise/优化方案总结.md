## 已完成的优化

### 1. BlockView 折叠/展开功能修复 ✅

**问题描述**：
在 `mindMapView.css`、`galleryView.css` 和 `boardView.css` 文件中，`.block-control` 被设置为 `display: none`，导致 Logseq 原生的折叠/展开按钮不可用。

**修复方案**：
已删除了这三个文件中的 `.block-control { display: none !important; }` 规则，现在用户可以正常折叠/展开节点了。

**修改文件**：
- `/workspace/src/components/BlockView/mindMapView.css`
- `/workspace/src/components/BlockView/galleryView.css`
- `/workspace/src/components/BlockView/boardView.css`

---

### 2. wrapWithQuotes 优化 ✅

**优化内容**：
重构了 `needsQuotes` 函数，使其更加智能地判断何时需要引号包裹：

1. 仅在包含普通空格（` `）时才强制需要引号
2. 添加了检查，当文本本身已被引号包裹时，不再重复包裹
3. 普通文本、连续特殊符号、中文标点文本等场景不再被不必要地包裹引号

**修改文件**：
- `/workspace/src/lib/textReplace/utils.ts`

---

### 3. 思维导图 Bullet 连线优化 ✅

**优化内容**：
采用了方案 1 + 方案 3 的组合优化：
1. 改进了现有连线样式，使垂直连线从顶部到底部完整连接
2. 调整了 bullet 点的位置，使其与连线完美对齐
3. 为所有层级的 bullet 点添加了 `z-index: 1`，确保显示在连线之上
4. 优化了连线的起始和结束位置，看起来更加自然流畅

**修改文件**：
- `/workspace/src/components/BlockView/mindMapView.css`

## 性能优化分析

### 1. BlockView 模块性能优化建议

**当前问题**：
1. `applyCustomTheme` 函数每次调用都会重新获取设置并生成 CSS 变量，即使设置没有变化
2. `applyViewStyle` 函数中先移除样式再添加样式，可能导致不必要的重绘
3. 没有对 DOM 元素查询结果进行缓存

**优化建议**：

```typescript
// 建议 1: 添加设置缓存
let settingsCache: any = null;
let lastSettingsFetchTime = 0;
const SETTINGS_CACHE_TTL = 1000; // 1秒

async function getCachedSettings(): Promise<any> {
  const now = Date.now();
  if (settingsCache && now - lastSettingsFetchTime < SETTINGS_CACHE_TTL) {
    return settingsCache;
  }
  settingsCache = await getSettingsWithSystem();
  lastSettingsFetchTime = now;
  return settingsCache;
}

// 建议 2: 优化 DOM 查询，添加缓存
const elementCache = new Map<string, HTMLElement>();
const ELEMENT_CACHE_TTL = 5000; // 5秒

function getCachedBlockElement(doc: Document, blockId: string): HTMLElement | null {
  const cached = elementCache.get(blockId);
  if (cached && doc.contains(cached)) {
    return cached;
  }
  const element = doc.querySelector(`[data-block-id="${blockId}"]`) || 
                 doc.querySelector(`#ls-block-${blockId}`);
  if (element) {
    elementCache.set(blockId, element as HTMLElement);
    // 清理过期缓存
    setTimeout(() => {
      if (elementCache.get(blockId) === element) {
        elementCache.delete(blockId);
      }
    }, ELEMENT_CACHE_TTL);
  }
  return element as HTMLElement | null;
}
```

### 2. textReplace 模块性能优化建议

**当前问题**：
1. `replaceText` 函数中有重复的逻辑分支（有换行和无换行处理有很多重复代码）
2. `parseNestedFormat` 函数可能在处理大量嵌套格式时效率不高

**优化建议**：

```typescript
// 建议 1: 提取公共逻辑，减少重复代码
function processSingleText(item: ToolbarItem, text: string): string {
  if (item.regex && item.replacement) {
    const regex = new RegExp(item.regex, 'g');
    return text.replace(regex, item.replacement);
  } else if (item.invokeParams) {
    // ... 原有的处理逻辑
  }
  return text;
}

// 建议 2: 使用更高效的字符串处理方式
// 对于频繁调用的 needsQuotes，可以考虑使用记忆化
const needsQuotesCache = new Map<string, boolean>();

export const needsQuotes = (text: string): boolean => {
  if (needsQuotesCache.has(text)) {
    return needsQuotesCache.get(text)!;
  }
  
  // 原有逻辑
  const result = text.includes(' ');
  
  // 限制缓存大小
  if (needsQuotesCache.size > 1000) {
    needsQuotesCache.clear();
  }
  needsQuotesCache.set(text, result);
  return result;
};
```

### 3. 工具栏模块性能优化建议

**当前问题**：
1. 事件监听器没有清理机制，可能导致内存泄漏
2. 配置解析没有缓存

**优化建议**：

```typescript

export class ToolbarManager implements IToolbarManager {
  private eventListeners: Map<string, Set<Function>> = new Map();
  
  // ... 现有代码

  reset(): void {
    this.isInitialized = false;
    // 清理所有事件监听器

    eventBus.clear();
  }

    actionExecutor.registerExecutor(id, handler);

  }

```

### 4. 渲染器参数模块性能优化建议

**当前问题**：
1. `findModel` 函数每次都遍历所有模型，可以优化
2. 正则表达式在 `createRendererArgUpdater` 中每次调用都重新创建

**优化建议**：

```typescript
// 建议 1: 为 findModel 添加前缀长度索引
const modelsByPrefixLength = new Map<number, Array<{ prefix: string; model: RendererArgModel }>>();

export function registerRendererArgModel(prefix: string, model: RendererArgModel): void {
  models.set(prefix, model);
  
  // 按前缀长度分组
  const len = prefix.length;
  if (!modelsByPrefixLength.has(len)) {
    modelsByPrefixLength.set(len, []);
  }
  modelsByPrefixLength.get(len)!.push({ prefix, model });
}

function findModel(type: string): { prefix: string; model: RendererArgModel } | null {
  // 从最长的前缀开始查找，提高匹配效率
  const lengths = Array.from(modelsByPrefixLength.keys()).sort((a, b) => b - a);
  
  for (const len of lengths) {
    const candidates = modelsByPrefixLength.get(len)!;
    for (const candidate of candidates) {
      if (type.startsWith(candidate.prefix)) {
        return candidate;
      }
    }
  }
  return null;
}

// 建议 2: 缓存正则表达式
const regexCache = new Map<string, RegExp>();

export function createRendererArgUpdater(prefixes: string | string[]): {
  updateRendererArgs: (content: string, updates: Record<string, string | null>) => string
} {
  const prefixList = Array.isArray(prefixes) ? prefixes : [prefixes];
  const cacheKey = prefixList.join('|');
  
  // 从缓存获取或创建新的正则表达式
  let rendererRegex = regexCache.get(cacheKey);
  if (!rendererRegex) {
    const prefixPattern = prefixList.map(p => 
      p.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')
    ).join('|');
    rendererRegex = new RegExp(`({{renderer\\s+(?:${prefixPattern})[^}]*?}})`, 'gi');
    regexCache.set(cacheKey, rendererRegex);
  }
  
  // ... 其余代码
}
```

## 前端组件性能分析

### 1. Heatmap 组件

**问题 1：Resize 处理中的事件监听清理风险**
- **风险点**：在组件卸载时，mousemove 和 mouseup 监听器没有统一的清理机制
- **建议**：使用 useRef 存储监听器引用，并在 useEffect cleanup 中统一清理

**问题 2：重复计算**
- **风险点**：dynamicStyle 计算在每次渲染时都在重新计算复杂的布局逻辑
- **建议**：将 getYearWeeksCount、calcCell 等函数提取到组件外部作为纯函数

### 2. Toast 组件

**问题 1：setTimeout 清理问题**
- **风险点**：快速添加多个 toast 时，timeout 没有完全清理
- **建议**：使用 useRef 存储所有 timeout id，并在 cleanup 中全部清理

**问题 2：全局对象挂载**
- **风险点**：没有类型不安全，没有命名空间隔离，可能与其他插件冲突
- **建议**：使用更安全的方式，例如通过事件总线或单例管理

### 3. TaskProgress 组件

**问题 1：useEffect 依赖不完整**
- **风险点**：依赖数组为空，但 ref 的值变化时不会重新执行
- **建议**：这是一个合理的设计，ref 的 cleanup 不需要依赖
